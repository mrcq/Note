# 驱动基础

## 驱动开发环境

- 下载内核头代码

	如果是给Ubuntu开发驱动，执行如下命令：

	```shell
	apt-cache search linux-headers-$(uname -r)       // 确认有没有
	sudo apt-get install linux-headers-$(uname -r)	 // 下载安装
	```

	- **从哪里安装**：从 `/etc/apt/sources.list` 配置的 Ubuntu 官方或镜像仓库下载
	- 安装到何处：
		- 头文件 → `/usr/src/linux-headers-$(uname -r)/`
		- 符号链接 → `/lib/modules/$(uname -r)/{build,source}`
	- **目的**：为编译内核模块（如驱动程序、VirtualBox 附加组件）提供必要的构建环境
	
	![](https://cdn.jsdelivr.net/gh/mrcq/Image@main/20250620154630057.png)
	
	如果是给开发板开发驱动，则需要下载开发板对应内核SDK

## 怎么找到驱动

- 通过打开驱动文件使用驱动
	
	驱动文件是特殊的文件，有类别（比如c字符设备）、主设备号、次设备号；Linux系统通过字符设备集、主设备号去定位到一个驱动程序
	
	![](https://cdn.jsdelivr.net/gh/mrcq/Image@main/20251011160120881.png)

## 怎么写驱动

1. 入口函数（内核调用入口函数、入口函数调用注册函数register_chrdev）、出口函数（调用注销函数unregister_chrdev）
2. 构造file_operations字符设备结构体（open、read、write等接口实现）
3. 确定主设备号
4. register_chrdev注册字符设备结构体（主设备号、名字、file_operations结构体）

## 内核与用户数据传输

在 Linux 内核驱动开发中，**`copy_to_user`** 和 **`copy_from_user`** 是两个核心函数，用于安全地在内核空间和用户空间之间传输数据。它们解决了用户空间内存访问的安全性问题，是字符设备驱动中 `read()`/`write()` 操作的基石。

- 为什么需要这两个函数？

	- **内存隔离**：用户空间内存不可直接被内核访问（反之亦然）
	- **安全性**：防止恶意用户空间程序传递非法地址导致内核崩溃
	- **缺页处理**：自动处理用户空间页错误（page fault）
	- **架构兼容**：统一不同CPU架构的内存访问方式

- copy_from_user

	**功能**：从用户空间复制数据到内核空间
	​**​典型场景​**​：驱动程序的 `write()` 操作中

- copy_to_user

	**功能**：从内核空间复制数据到用户空间
	​**​典型场景​**​：驱动程序的 `read()` 操作中

## 内核与硬件数据传输

在 Linux 内核驱动开发中，驱动程序无法直接操作物理地址，而必须通过虚拟地址（配合 `ioremap` 映射）访问硬件。这是由现代操作系统的内存管理机制（MMU）和安全性设计决定的。

### 为什么需要 `ioremap`

CPU 启用内存管理单元（MMU）后，所有程序（包括内核驱动）都运行在虚拟地址空间中。
 物理地址由 MMU 动态映射，驱动若直接访问物理地址会导致以下问题：

- **非法访问**：可能覆盖内核或其他进程的内存区域
- **硬件冲突**：外设寄存器通常位于物理地址空间，直接访问可能引发总线错误或设备损坏
- **安全风险**：绕过 MMU 会破坏内存隔离机制，影响系统稳定与安全

### `ioremap`

**功能**：
 将设备的物理 I/O 地址空间映射到内核虚拟地址，使驱动能通过虚拟地址访问外设寄存器或专用内存区域。

**典型场景**：
 用于映射 GPIO、UART、PCIe、DMA 控制器等**具备内存映射寄存器（MMIO）**的硬件。
 驱动在初始化阶段执行 `ioremap()` 获取虚拟基址，通过 `readl()/writel()` 完成寄存器读写。

### 并非所有硬件都通过 `ioremap`

`ioremap` 只适用于 **CPU 可直接寻址的寄存器区域**。
 对于一些通过通信总线连接的外设（如 **触控屏、传感器、EEPROM** 等），
 它们并不位于 CPU 物理地址空间中，而是通过 **I²C、SPI、UART** 等总线由主控发送命令帧完成数据交互。

在这类设备中：

- 驱动不直接访问寄存器地址，而是调用总线接口函数（如 `i2c_transfer()`、`spi_sync()`）；
- 数据传输由内核的 I²C/SPI 控制器驱动完成；
- 因此**不需要也无法使用 `ioremap`**。
