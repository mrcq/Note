# 最简单的驱动程序

## **驱动代码**

```c
#include <linux/module.h>  // 模块基础功能头文件

int init_module(void) {
    return 0;
}   // 内核默认入口函数（加载时执行）

void cleanup_module(void) {} // 内核默认出口函数（卸载时执行）

MODULE_LICENSE("GPL");     // 许可证声明（必须）
```

**关键组成**：

- **入口/出口函数**：`init_module` 和 `cleanup_module` 是内核默认函数名，无需额外声明。
- **许可证**：`GPL` 避免内核污染警告。

 **常用指令**

|   命令   |            功能            |         示例          |
| :------: | :------------------------: | :-------------------: |
| `insmod` |   加载模块（需完整路径）   | `insmod hello_drv.ko` |
| `lsmod`  |       查看已加载模块       | `lsmod | grep hello`  |
| `rmmod`  |          卸载模块          |   `rmmod hello_drv`   |
| `dmesg`  | 查看内核日志（printk输出） | `dmesg | tail -n 10`  |

## **`init_module` 与 `module_init` 的关系**

 **为什么 `init_module` 可直接替代自定义函数？**

- 历史兼容性：init_module是内核原始入口函数名，直接使用可避免额外宏定义。

- `module_init` 的宏展开（v5.4.150 源码）：

	```c
	#define module_init(initfn)                    \
	    static inline initcall_t __maybe_unused __inittest(void) \
	    { return initfn; }                        \
	    int init_module(void) __copy(initfn) __attribute__((alias(#initfn)));
	```

	**逐步解析**：

	1. **`__inittest`**：静态内联函数，编译时检查 `initfn` 是否符合 `initcall_t` 类型（返回 `int` 且无参数）。
	2. **`init_module` 声明**：
		- __attribute__((alias(#initfn)))：将 `init_module` 定义为 `initfn` 的别名，确保调用 `init_module` 实际执行 `initfn。
		- `_copy(initfn)`：复制函数属性（如 `__init` 标记）到 `init_module。

	 **设计目的**

	- **统一入口**：无论使用 `module_init(my_init)` 或直接定义 `init_module`，最终函数地址均被链接到 `.initcall6.init` 段（优先级6）。
	- **灵活性**：`module_init` 允许自定义函数名（如 `my_init`），而 `init_module` 提供向后兼容。

## **Makefile 解析**

 **代码结构与机制**

```makefile
KVERSION = $(shell uname -r)          # 获取当前内核版本
KERN_DIR = /lib/modules/$(KVERSION)/build  # 内核头文件目录

all:
    make -C $(KERN_DIR) M=$(PWD) modules  # 核心编译命令

clean:
    make -C $(KERN_DIR) M=$(PWD) clean    # 清理构建文件

obj-m += hello_drv.o                     # 编译目标（生成 hello_drv.ko）
```

**关键机制**：

- **`-C $(KERN_DIR)`**：切换到内核构建目录，复用内核的编译配置和头文件。
- **`M=$(PWD)`**：指定模块源码路径，内核构建系统自动处理依赖和符号表。
- **`obj-m`**：声明编译为可加载模块（`.ko` 文件）。

> **为何不用 gcc 直接编译？**
> 内核模块需链接内核符号表，且依赖内核头文件配置（如 `CONFIG_` 选项），必须通过内核构建系统编译。

## **`printk` 的使用与内核缓冲区**

 **添加 `printk` 的驱动示例**

```c
#include <linux/module.h>

int init_module(void) {
    printk(KERN_INFO "Driver loaded\n");  // KERN_INFO 为日志级别
    return 0;
}

void cleanup_module(void) {
    printk(KERN_ALERT "Driver unloaded\n"); // KERN_ALERT 高优先级
}

MODULE_LICENSE("GPL");
```

**间接包含机制**：

- `<linux/module.h>` 已经间接包含了 `<linux/kernel.h>`。
- `<linux/kernel.h>` 又包含了 `<linux/printk.h>`。

**常见日志级别**：

```c
KERN_EMERG   "<0>"  // 系统不可用（最高）
KERN_ALERT   "<1>"
KERN_CRIT    "<2>"
KERN_ERR     "<3>"
KERN_WARNING "<4>"  // 默认级别
KERN_NOTICE  "<5>"
KERN_INFO    "<6>"  // 信息性消息
KERN_DEBUG   "<7>"  // 调试信息（最低）
```

**为何用 `printk` 而非 `printf`？**

|   **特性**   |                 **printk**                  |     **printf**     |
| :----------: | :-----------------------------------------: | :----------------: |
| **运行空间** |                   内核态                    |       用户态       |
| **输出目标** |               内核环形缓冲区                | 标准输出（如终端） |
|  **优先级**  | 支持8个级别（如 `KERN_EMERG`~`KERN_DEBUG`） |    无内置优先级    |
| **线程安全** |          是（可在中断上下文使用）           |         否         |

**内核环形缓冲区（Ring Buffer）**：

- **位置**：内核空间的一段循环内存区，大小固定（默认 16KB，可通过 `syslog` 配置）。
- **特性**：
	- 新消息覆盖旧消息，避免内存耗尽。
	- 通过 `dmesg` 或 `/var/log/kern.log` 查看。

> **调试技巧**：
> `echo 8 > /proc/sys/kernel/printk` 降低控制台日志级别阈值，确保低优先级消息可见。

## **`__init` 与 `__exit` 的作用**

 **添加宏后的代码**

```c
#include <linux/module.h>

int __init init_module(void) {
    printk(KERN_INFO "Driver loaded\n");
    return 0;
}

void __exit cleanup_module(void) {
    printk(KERN_ALERT "Driver unloaded\n");
}

MODULE_LICENSE("GPL");
```

 **宏的作用机制**

|    **宏**    |                   **作用**                   |                         **内存管理**                         |
| :----------: | :------------------------------------------: | :----------------------------------------------------------: |
| **`__init`** | 标记初始化函数，将其代码放入 `.init.text` 段 | 内核启动完成后释放此段内存（通过 `free_initmem()`），节省内核常驻内存。 |
| **`__exit`** |      标记退出函数，放入 `.exit.text` 段      | 静态编译进内核的模块直接丢弃此代码；动态加载模块保留供卸载时调用。 |

> **设计哲学**：
> 通过段隔离 ​**​临时性代码​**​（初始化/卸载），最大化利用有限内核内存。
